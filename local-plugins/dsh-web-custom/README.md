# DSH Web customization

English | [中文](README.zh.md)

Sign in to DeepSeek Harness Web with local accounts and disable conversation likes, dislikes, and feedback dialogs. The login page uses Hengshu’s pale green theme, places the brand introduction beside the form on desktop and above it on narrow screens, and supports showing or hiding the password. Sign-in requires a username, password, and a four-digit, one-use verification image generated by DSH; click the image or “New image” to refresh it. Leading zeroes are supported. Refresh keeps the current image until its replacement has loaded, then shows a confirmation; sign-in remains disabled while the form keeps its appearance. The account database lives in the DSH data directory, passwords use Argon2id hashes, and sessions use an HttpOnly JWT cookie.

## Build and install

Use Node.js 24.9 or later. First run `pnpm install` and `pnpm run build:artifacts` from the DSH repository root. This plugin lives in the fork’s `local-plugins/` directory and has its own dependency manifest and lockfile. Its development dependencies use DSH types and runtime artifacts generated by the current checkout.

Continue from the DSH repository root to build the plugin and create an account.

```sh
pnpm -C local-plugins/dsh-web-custom install --frozen-lockfile
pnpm -C local-plugins/dsh-web-custom run build
node local-plugins/dsh-web-custom/lib/create-user.js operator
```

The account creation command hides password input in the local terminal. The package command is named `dsh-web-custom-user`. The default database is `${DSH_HOME:-$HOME/.dsh}/auth/users.sqlite`. Existing databases use the same path, so existing accounts can still sign in. Each account has owner access to this DSH instance.

For initial activation, install the composition bundle into the `web` profile, then start Web. If the profile has the old `dsh-web-login` package installed, follow the migration instructions below first.

```sh
pnpm dsh plugin --profile web add ./local-plugins/dsh-web-custom
pnpm dsh web
```

If the `web` profile is not initialized, run `pnpm dsh web --dump-config` before installation. Installation updates the Web profile and its dependency manifest. The composition bundle disables the default launch-token authentication and mounts password authentication; subsequent launches can start Web directly.

The login page and main interface use the Hengshu logo as their browser tab icon. After sign-in, the top-left corner shows the Hengshu logo and name; collapsing the sidebar keeps only the logo. The logo also appears before the new-conversation heading, and plugin styles hide its adjacent preview badge. These styles depend on the homepage heading and badge being adjacent and require verification after upstream upgrades. The bottom-left corner shows the local username and an initial avatar. Clicking the avatar opens a menu above the account row with their left edges aligned, where you can open settings or sign out of the current browser’s local session. The plugin disables the Web DeepSeek sign-in service, account-based model routing, the account and balance settings page, and account notifications.

This Web profile does not use saved DeepSeek account grants. Model settings support API keys. If an existing conversation selected a DeepSeek account model, choose a configured model in the model selector.

After a linked installation from the local directory, run `pnpm -C local-plugins/dsh-web-custom run build` again and restart Web whenever you update the composition bundle.

Uninstall with `pnpm dsh plugin --profile web remove dsh-web-custom`. On the next launch, Web restores the profile’s default authentication and feedback interface. The account database remains in the DSH data directory.

## Migrate from the old package name

After building the new package, stop the running Web instance, switch the package name, and start Web again. Existing accounts keep using the same database, so you can skip account creation.

```sh
pnpm dsh plugin --profile web remove dsh-web-login &&
pnpm dsh plugin --profile web add ./local-plugins/dsh-web-custom &&
pnpm dsh web
```

## Configuration

The composition bundle loads the [authentication patch](auth.patch.yml) followed by the [interface patch](ui.patch.yml). To restore likes, dislikes, and feedback dialogs, override the following entry in the Web profile’s `cordis.patch.yml`:

```yaml
- id: ui-message-feedback
  disabled: false
```

The `/feedback <content>` command can still submit conversation feedback when it includes a message.

The composition bundle sets secure cookies according to the Web entry’s TLS configuration or public HTTPS URL. Plain HTTP accepts only loopback addresses. When deploying behind a TLS proxy, pass the external HTTPS URL to Web’s `--public-url` and configure trusted hosts for the deployment.

To customize the database path or session duration, override the complete `config` of `web-password-login` in the Web profile’s `cordis.patch.yml`. The database path must be absolute; the account creation command also accepts it as its second argument. JWTs are valid for eight hours by default, and verification images for three minutes.

## Upstream upgrades

After merging upstream updates and rebuilding DSH, run `pnpm run check` and `pnpm test` in `local-plugins/dsh-web-custom/`, then verify sign-in and refresh using the Web profile. If upstream changes the authentication interface, update the plugin implementation and dependency ranges in this directory.
